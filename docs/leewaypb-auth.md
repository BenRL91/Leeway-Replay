# LeewayPB sign-in in Leeway Replay

The existing shared Supabase Auth project and publishable configuration were reused from the authorized Pickle Point sign-in handoff. Only Leeway Replay was modified; shared provider settings, Site URL, other callbacks, email templates, payments and other apps were not modified. The user reports adding the exact Leeway Replay callback to the shared allowlist.

Login: `/leeway-account`. Callback: `/auth/return`. Both use a no-store/no-referrer shell. Query/fragment callback parameters are cleared before further page requests. Email PKCE and verification-code support, Google and Apple availability follow public provider settings. Actual provider completion and email-template routing still need a human sign-in test. No sign-in or customer email was sent by the agent.

The Supabase SDK version is pinned to the supplied compatibility baseline, 2.117.1. Only a one-hour PKCE verifier persists in browser storage. The browser transfers the verified sign-in's refresh token once to its own session endpoint. Host-only `__Host-yoututor-access` and `__Host-yoututor-refresh` cookies are Secure, HttpOnly, SameSite=Lax. Each data actor is checked with the provider, not trusted from a cached client session, email, or editable user metadata. Anonymous identities are rejected. Refresh persists both rotated cookies, coalesces same-token refresh requests within a Worker for ten seconds, and verifies cached refresh identity again. Across Workers the provider's refresh-reuse rules apply; no distributed refresh coordinator was introduced.

Auth mutations require the exact same Origin and `x-leeway-session: 1`. Responses containing credentials use private/no-store and do not return tokens in JSON. Sign-out revokes this app's current provider session when reachable and clears both cookies; it never deletes content. Provider failures preserve existing data. There is no service-role key.

The first owner sign-in requires an explicit confirmation showing the verified user. Only the existing private Sites owner may confirm that connection. A conditional R2 record at `auth/owner-link.json` binds the verified issuer/subject to the legacy storage identity; a different subject cannot replace it. Nothing is copied or erased, and an equal email never authorizes a library claim. The confirmed owner keeps all original namespaces and review ownership. Non-owner identities use `supabase_<verified subject>` namespaces and cannot edit coaching reviews. The access ID shown by `/api/replay/identity` remains supported for per-review grants. Recipient-email sharing uses only the server-verified Supabase user email and email_confirmed_at; it never grants owner privileges.

The app audience is private and includes the original owner plus the explicitly admitted viewer benlee.eelned@gmail.com. Replay alone supports per-review recipient email sharing; no shared auth settings or Coaching orders/delivery have changed. Direct browser WebKit and actual email/Google/Apple completion remain unverified. Automated checks cover rejection, linking, preservation, cookie security/rotation, callback transfer, PKCE persistence and cross-account isolation.

Legacy browser-note migration is allowed only for the original owner storage identity while that original Sites owner is present. Another signed-in LeewayPB account cannot import that browser's old notes automatically. Account changes detected on focus/session checks reload the page to discard stale account-scoped UI state.

### App-private beta and custom domain

The active runtime uses `LEEWAY_ACCESS_MODE=allowlist` and server-configured `LEEWAY_APPROVED_EMAILS`. Both owner and testers must have an email confirmed by Supabase getUser. Owner email maps to original coach storage; students keep their subject-derived IDs. Protected HTML routes redirect to sign-in before returning the application shell. Every content/media API rejects anonymous/unapproved users, independent of Sites identity headers; empty approval configuration or missing auth configuration fails closed. Sign-in only establishes app cookies for approved users. Removed testers lose access on their next request, while review grants/revocation remain an additional authorization layer. Platform public admission removes the ChatGPT gate but does not expose stored content.

`LEEWAY_ALLOWED_ORIGINS` accepts the generated origin and `https://replay.leewaypb.com`; callbacks use the initiating approved origin. No wildcard or caller-selected external callback is accepted. The custom domain is pending DNS validation. Its exact callback is `https://replay.leewaypb.com/auth/return`. Add it to Supabase Redirect URLs without changing global auth settings for other apps. Existing sessions are host-only, so sign in once on the new host.

Additional Replay testers may be configured in `LEEWAY_ADDITIONAL_APPROVED_EMAILS` (comma-separated), preserving the existing secret `LEEWAY_APPROVED_EMAILS`. Both lists require server-verified confirmed email and grant student admission only. To revoke a tester, remove the address from both lists. Review sharing remains separately enforced. PaddleLog tester approval does not automatically grant Replay admission.
